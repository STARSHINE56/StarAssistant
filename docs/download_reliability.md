# 内置下载器稳定性与吞吐优化

基线：4f1b04e（星辰助手 1.1.4）。本改动不接入 AI，不替换图标图片，不改网盘认证及来源限制。

## 已实现

- 图标入口使用实际 MainActivity 类型及本包 alias；先检查禁用组件也存在。API33+批量提交，旧系统先启目标后禁旧，失败尽可能回退；成功才更新 UI/设置，异常不再导致闪退。
- worker 只在首次请求错峰，去掉主池每片额外 200ms 等待。
- 保留合法旧 plan；并发配置改变不改变已有文件区间。大小变化/无效计划清理不可信缓存。
- 弹性区保留完整及部分分片，填补中间空洞；拒绝重叠、越界和超长片。恢复进度以验证过的磁盘长度为准。
- 下载及修复共享一个慢连接看门狗。阻塞建连/读取使用取消监视，不需等待60秒读超时；抢占主动取消当前 Call，再按已写长度续传。
- 正常及补片统一进度落盘节流、速度采样和通知逻辑。
- 每任务从最多8路开始，5秒窗口采样；试探增加到用户上限，吞吐未提升10%时回到原档并冷却。429/503 按有界 Retry-After 冷却、减并发；Java堆高压同样减并发。
- 全局按堆预算并保守封顶128路，不再只按64KB读缓冲宣称512路安全。迅雷仍最多8路，旧设置不丢失。Gopeed 保持独立策略。
- 弹性分片按近期单路吞吐估计约8秒工作量，在1～16MiB之间调整；已有区间永不重划。
- 遇到 Range 200 停止分配新片、等待当前请求退出，在单路低并发下再验证两次。只有再次返回200才整文件回退；补片失败/超时本身不触发从头重下。
- 探测并记录 ETag/Last-Modified；恢复使用强ETag或合法HTTP日期的If-Range，拒绝校验后200、变化的ETag/总长度。刷新链接可提供不同内容标识时拒绝续传。
- 最终合并前验证长度总和。仍然禁止把整文件200响应写到分片。

## 兼容与安全取舍

- If-Range返回200既可能是内容变化，也可能是源不支持条件Range。已有前缀时为安全拒绝续传，不把它当作普通Range降级；需要重新下载。
- 没有ETag/Last-Modified且平台不提供摘要的源，只能做区间/长度校验，不能保证同尺寸内容未发生变化。
- Retry-After限制最大120秒，防恶意/异常响应无限阻塞；反复限流仍经任务有限重试处理。
- 128不是所有机型的精确资源模型或绝对安全保证；仍需真实机型、热/电/存储压力验证。
- 试探策略可能受CDN波动影响；不是已证明在所有网盘跑满带宽的算法，也不会绕过账号/IP限速。

## 本轮未引入的复杂改造

- 普通文件单目标随机写、SAF兼容双路径及断电恢复：保持现有边合并边删架构，避免在未验证文件系统事务前引入数据损坏风险。
- 运行中把活跃慢区间拆分给其他worker：保留有限换连接策略，未并行重划已经领取的区间。
- 按host/网络持久化最佳并发、native堆/FD/热状态动态预算、服务端文件摘要验收。
- Gopeed内部调度、厂商省电策略、真实网盘登录及测速未由单元测试覆盖。

## 验收

CI执行全部JUnit、Android Lint和Debug APK构建。新增覆盖：旧计划兼容、尾部部分片及空洞、重叠/超长拒绝、并发增减与冷却、取消等待、HTTP429、内容标识变化、Range保护、阻塞取消及抢占续传。

真机需要：经典/新图标来回切换后从桌面启动；新旧任务恢复及调线程不丢进度；大文件暂停/进程重启；直链过期；无Range源；429源；锁屏长下载。对同文件同网络比较持续速度、尾段时间及完整文件SHA256，不能仅看峰值。
